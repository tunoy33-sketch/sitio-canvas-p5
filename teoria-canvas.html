La etiqueta <canvas> y el contexto 2D

Cómo el navegador permite dibujar píxeles directamente desde JavaScript.

¿Qué es la etiqueta canvas?

La etiqueta <canvas> es un elemento de HTML5 que reserva en la página un rectángulo de píxeles sobre el cual un programa de JavaScript puede dibujar. A diferencia de elementos como <div> o <svg>, las figuras que se pintan dentro de un canvas no se convierten en nodos del DOM: el navegador solo conserva un mapa de bits y no recuerda qué formas lo componen. Por eso se dice que canvas funciona en «modo inmediato». Cada instrucción de dibujo pinta píxeles en el momento en que se ejecuta y, si se quiere mover o borrar algo, hay que volver a pintar la escena. Es exactamente lo que hace la función draw() de p5.js en cada cuadro de una animación.

Esta característica explica sus ventajas y sus límites. Dibujar miles de elementos es muy rápido porque no hay un árbol de objetos que mantener, lo que hace al canvas ideal para juegos, simulaciones, visualizaciones y arte generativo. A cambio, un canvas no ofrece por sí mismo detección de clics sobre una figura concreta, ni estilos CSS por figura, ni accesibilidad nativa para su contenido: todo eso debe programarse manualmente.

Atributos y sistema de coordenadas

Un canvas se declara con los atributos width y height, que fijan la resolución interna del lienzo en píxeles (300 por 150 si se omiten). Conviene no confundir esa resolución con el tamaño visible en pantalla, que controla CSS: si una hoja de estilos hace el canvas más ancho de lo que indica su atributo width, el navegador escala el mapa de bits y la imagen se ve borrosa. Entre las etiquetas de apertura y de cierre puede escribirse un texto alternativo que verán los lectores de pantalla y los navegadores sin soporte. 

<canvas id="lienzo" width="400" height="400">
  Dibujo de una rana sobre un nenúfar.
</canvas>

El sistema de coordenadas del canvas tiene su origen (0, 0) en la esquina superior izquierda. El eje x crece hacia la derecha y el eje y crece hacia abajo, al contrario que en un plano cartesiano de matemáticas. Este es el mismo sistema que utiliza p5.js y el simulador de Khan Academy, de modo que las coordenadas de los dibujos originales se conservan sin cambios.

El contexto de renderizado 2D

El elemento <canvas> por sí solo no dibuja nada: es únicamente la superficie. Para dibujar hay que pedirle un «contexto de renderizado», que es el objeto que contiene la API de dibujo. Eso se hace con el método getContext(), indicando el tipo de contexto deseado. Al pedir '2d' se obtiene un objeto CanvasRenderingContext2D, tradicionalmente guardado en una variable llamada ctx. Un mismo canvas solo puede tener un tipo de contexto: una vez que se solicitó el contexto 2D, pedir uno de WebGL devuelve null. 

const lienzo = document.getElementById('lienzo');
const ctx = lienzo.getContext('2d');

ctx.fillStyle = 'seagreen';
ctx.fillRect(50, 50, 120, 80);   // rectángulo relleno en (50, 50)

La API del contexto 2D se organiza en varias familias de operaciones. Los rectángulos se pintan con fillRect(), strokeRect() y clearRect(). Las formas arbitrarias se construyen como trazados: se llama a beginPath(), se añaden segmentos con moveTo(), lineTo(), arc() o bezierCurveTo(), y finalmente se rellena con fill() o se dibuja el contorno con stroke(). El aspecto lo determinan propiedades como fillStyle, strokeStyle, lineWidth y globalAlpha, y los degradados se crean con createLinearGradient() y createRadialGradient(). También existen el texto (fillText() y la propiedad font), las imágenes (drawImage()) y las transformaciones (translate(), rotate() y scale()), que se pueden aislar guardando y restaurando el estado del contexto con save() y restore(). Esas dos últimas son el equivalente directo de push() y pop() en p5.js. 

ctx.beginPath();
ctx.arc(200, 200, 60, 0, Math.PI * 2);  // círculo de radio 60
ctx.fillStyle = '#60b5f5';
ctx.fill();
ctx.lineWidth = 4;
ctx.strokeStyle = '#0f172a';
ctx.stroke();

Animación con requestAnimationFrame

Como el canvas no recuerda lo que contiene, una animación consiste en repetir un ciclo: borrar el cuadro anterior, actualizar las posiciones y volver a dibujar. Para repetirlo en el momento adecuado se usa requestAnimationFrame(), que pide al navegador ejecutar una función justo antes del siguiente refresco de pantalla, normalmente unas sesenta veces por segundo, y que se pausa sola cuando la pestaña no está visible. Otros contextos de renderizado

El contexto 2D no es el único que admite un canvas. Con getContext('webgl') o getContext('webgl2') se accede a la tarjeta gráfica mediante una API basada en OpenGL ES, pensada para gráficos tridimensionales y programas sombreadores escritos en GLSL. El contexto 'bitmaprenderer' se limita a mostrar imágenes ya procesadas en forma de ImageBitmap, y el más reciente, 'webgpu', expone la API WebGPU para cálculo y gráficos de bajo nivel. Existe además OffscreenCanvas, una variante que permite dibujar en un Web Worker sin bloquear la interfaz. Este proyecto utiliza únicamente el contexto 2D, que es el más sencillo y el que corresponde a los dibujos de Khan Academy.

Buenas prácticas

En pantallas de alta densidad, un canvas dibujado a su resolución nominal puede verse algo borroso; la solución habitual es multiplicar width y height por window.devicePixelRatio y reducir el tamaño visible con CSS (p5.js hace este ajuste de forma automática). Con respecto a la accesibilidad, conviene añadir siempre un texto alternativo dentro de la etiqueta o un atributo aria-label que describa el dibujo. En cuanto al rendimiento, es recomendable no crear objetos nuevos dentro del ciclo de animación, dibujar una sola vez los fondos que no cambian y apilar varios canvas cuando una parte de la escena se actualiza mucho más a menudo que otra. Los cinco dibujos de este sitio son escenas estáticas, así que se pintan una única vez y no necesitan ningún ciclo de animación.
